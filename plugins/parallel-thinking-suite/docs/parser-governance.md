# 解析器治理规范

本规范覆盖解析器从发现到停用的完整生命周期。目标是在文件类型逐步增加时，让新增解析能力可追踪、可验证、可灰度、可回滚，不因为一个不可信或不稳定的解析器破坏整次并行运行。

## 1. 所有权与真相源

- 内置解析器随插件版本发布，默认状态为 active，不能从界面停用。
- 扩展解析器只从全局目录 parsers/<id>/<version>/ 发现，不访问远程 marketplace，不下载代码。
- 每个版本必须包含 manifest.yaml 与本地入口 .js 或 .mjs。
- registry.json 记录生命周期、当前/上一稳定版本、运行指标和最后错误；项目解析缓存另存，不替代 registry。

最小 manifest：

    id: custom-parser
    version: 1.0.0
    extensions: [.custom]
    entry: index.mjs

入口协议：

- 第一个命令行参数是输入文件绝对路径。
- stdout 必须只输出一个 JSON 对象，至少包含字符串字段 text。
- stderr 可写诊断；不能把密钥、请求头或输入全文写入日志。
- 15 秒内必须退出；非零退出码、超时、无效 JSON 或缺少 text 都是硬失败。

## 2. 生命周期状态

    discovered → validating → canary → active → deprecated → disabled
                        └────→ failed
                 canary/runtime ────→ rolled_back

- discovered：manifest 被发现，但未准入。
- validating：检查 manifest、路径边界、入口存在性和 JavaScript 语法。
- canary：在最多 5 个真实候选文件上同时运行当前稳定解析器与新版本。
- active：可被知识路由器选择。
- deprecated：保留用于回滚，不再处理新文件。
- disabled：人工停用；文件保留，可恢复。
- failed：准入检查未通过。
- rolled_back：灰度或运行期硬失败触发回滚。

任何无记录的跳级都不允许。内置解析器升级也应在发布前执行同等回归测试。

## 3. 准入检查

扩展版本进入灰度前必须同时满足：

- ID 是小写 kebab-case，版本是严格 semver。
- 文件扩展名列表非空并统一转为小写带点形式。
- 入口路径解析后仍位于该解析器版本目录内。
- 入口只允许 .js 或 .mjs，且通过 node --check。
- 代码经过人工静态检查，重点检查网络访问、进程创建、任意路径读取、环境变量读取、动态执行和超大输出。
- 不以 Node 权限模式替代静态检查；权限模式只是降低意外损害的安全带。

## 4. 灰度规则

- 选择最多 5 个与扩展名匹配的真实知识库文件。
- 同时运行当前内置/稳定解析器和候选版本。
- 候选崩溃、超时、Schema 不合法，立即 rolled_back。
- 旧解析器有非空内容而新解析器为空，立即 rolled_back。
- v1 不自动判断语义质量；启用前仍应人工抽查至少一个完整输出。
- 灰度通过后，新版本变为 active，此前 active 版本变为 deprecated 并记录为 previousStableVersion。

没有候选文件时允许技术性启用，但必须明确视为“未完成真实文件验证”，首次运行纳入重点观察。

## 5. 运行隔离

- 扩展在独立 Node 子进程运行，启用 --permission。
- 只授予解析器自身目录与当前输入文件的读取权限；默认不授予写权限、子进程、Worker、原生 addon 或网络能力。
- 子进程环境只保留运行所需的 PATH、SystemRoot、TEMP、TMP；不得继承 OpenAI、Anthropic、DeepSeek 密钥。
- 单次运行上限 15 秒，父进程负责终止超时子进程。
- 不支持的文件应显式标记“跳过”，不得让整个 Agent 运行失败。
- 子进程同样不得继承 OpenRouter 密钥或归因请求头配置。

## 6. 自动回滚

- 每次硬失败增加 consecutiveHardFailures。
- 一次成功即把连续硬失败归零。
- 同一 active 扩展连续 3 次硬失败，立即标记 rolled_back。
- 如果存在 previousStableVersion，自动恢复其 active 状态；否则回退到支持该扩展名的内置解析器。
- 回滚保留失败版本、指标和最后错误，不直接删除，便于复盘。

## 7. 缓存与版本

- 缓存键必须包含：文件 SHA-256、解析器 ID、解析器版本。
- 解析器版本变化不能复用旧缓存。
- 缓存只保存提取后的文本、来源路径、解析器版本和非敏感元数据。
- 同一解析器至少保留当前 active 与 previous stable 两个版本；清理更早版本前先确认无项目缓存或审计依赖。

## 8. 指标与审计

每个版本至少记录：

- 成功次数、失败次数、连续硬失败数。
- 总耗时，可据此计算平均耗时。
- 提取字符总数、缓存命中次数。
- 最后使用时间、最后错误。
- 状态变化及回滚结果。

运行事故复盘必须能回答：哪个版本、哪个输入类型、何时失败、是否产生部分结果、回滚到什么版本、是否影响其他 Agent。

## 9. 变更、弃用与删除

- 修改解析逻辑必须发布新版本，不能静默覆盖 active 版本。
- deprecated 至少保留一个观察周期；确认新版本稳定后才可 disabled。
- 删除是人工且可恢复的维护动作，不由运行时自动执行。
- 扩展名所有权冲突时，最高版本的 active 扩展优先；没有 active 扩展则回到内置解析器。
- 安全事件、输出污染或疑似密钥访问不等待 3 次失败，人工立即停用并进行静态审计。
